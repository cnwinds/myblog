# 实验室

`/lab` 是项目展示页，数据仍是 `category: 'lab'` 的文章，没有单独的项目表。

## 页面

- 顶部是类型筛选徽章：「全部」默认选中；其余徽章来自当前实验室文章的 `tags`（按出现次数降序，次数相同再按名称）
- 点击标签只显示含该标签的项目；再点「全部」清除筛选。已选中的标签再点一次保持不变
- 筛选结果为空时显示「该类型暂无项目」
- URL 可用 `?tag=游戏` 同步当前筛选
- 卡片网格：桌面 2–3 列，手机 1 列
- 列表按 `createdAt` 倒序（新的在前）；不再支持拖拽改序
- 封面优先取正文第一张 Markdown 图片（`<img>`，16:9）；没有图片时用浅色占位
- 标题、一行简介（`excerpt`，否则取正文第一行非图片文本）
- `tags` 显示为标签
- 有 `demoUrl` 显示「体验」，有 `repoUrl` 显示「GitHub」，新标签打开，不进入文章
- 点击卡片其余区域进入 `/article/:id`
- 实验室文章详情页在标题（及标签，如有）下方展示同样的「体验」/「GitHub」入口；按钮旁附完整 URL，方便复制。未填写的字段不显示对应按钮。博客文章不展示该区块

## 可选字段

| 字段 | 存储 | API |
| --- | --- | --- |
| `demoUrl` | TEXT，可空 | `string \| null` |
| `repoUrl` | TEXT，可空 | `string \| null` |
| `tags` | TEXT JSON，如 `["游戏","AI"]` | `string[]` |

旧文章没有这些列时，迁移会补空列；接口返回 `demoUrl`/`repoUrl` 为 `null`，`tags` 为 `[]`。博客文章不受影响。

创建 / 更新 / 一键发布都可以带这些字段。编辑器仅在分类为「实验室」时显示。
